# BOTTLE KEEPER | MVP仕様 v0.1

- 状態：企画・未実装。数値はプレイテスト前の初期仮説。
- ジャンル：縦画面・物理お手玉アクション／エンドレス・スコアアタック
- 一言：「落とすな。回して、狙って、もう一発。」

## 1. 完成形の体験（North Star）
プレイヤーは画面下を左右に動く小さな空気砲を操作する。空中で落ちてくるガラス瓶を下から撃ち上げる。命中位置によって瓶の跳ねる方向と回転が変わり、次の一発が少しずつ難しくなる。やがて瓶が2本、3本と増え、危ない一本を救っては次を追う。落とせば割れる。結果画面からすぐ再挑戦。「瓶に振り回されていたのに、いつの間にか瓶を操っている」が目標体験。

**最小感動体験（MDE）**：偏った位置を撃つ→瓶が斜めに回転しながら跳ぶ→先回りして落下寸前を打ち返す→自分の上達を感じる。音、回転、軌道が一体になった数秒間。

## 2. コアルール
1. 瓶には重力が働き、落下する。開始時は1本。
2. プレイヤーは左右移動し、真上へ空気弾を発射する（射角は固定）。
3. 弾が瓶に当たると上向きの衝撃が入り、**接触位置・瓶の向き・回転状態**によって横方向の移動と回転が変わる。
4. 瓶が底の失敗ライン（床）に触れると、1本でもゲームオーバー。左右の壁は反射する。
5. 合計命中回数が目安8回で2本目、22回で3本目を予告して投入。最大3本。同時に増えるのではなく、危険な瞬間の追加は少し延期する。
6. クリアや制限時間はない。自己ベスト更新を目指す。

## 3. 操作
- PC：マウス左右移動＋クリック射撃。代替：A/Dまたは←/→で移動、Spaceで射撃。
- スマホ：左下エリアをドラッグして移動、右下エリアをタップして射撃。マルチタッチ対応。ボタンは画面下に薄く表示。
- 連射は可能だがショット間隔は初期値0.30秒。弾数制限・リロードなし。外しても失点しないが、次の発射まで待つ。
- 手動照準、上向き以外のショット、長押しオート連射はv0.1に入れない。

## 4. 瓶の物理と「上達できる」設計
- 瓶は**胴・肩・首・口**の異なる輪郭を持つ剛体とする。一本の剛体に複数の衝突形状を持たせ、回転で当たりやすい箇所が変わる。
- ほぼ重心線を通る命中は上方向へ安定して飛ぶ。左右にずれた命中は回転トルクと横向きの変化が生じる。斜めの瓶を撃つと接触面の向きにも影響される。
- 同じ位置・速度・角度・入力であれば同じ結果になる。乱数で落下軌道を乱さない。
- 厳密な現実物理より「当たれば気持ちよく再上昇する」「結果を学習できる」を優先。必要なら命中後の最低上昇速度と最大角速度を補正する。**回転そのものを自動で戻すアシストは入れない。**
- 瓶の横速度、最大角速度、反射係数、重力、衝撃量はデバッグUIで調整可能にする。画面外に長時間消えないよう天井も緩く反射。
- 細い口で弾がすり抜けたり高速弾が貫通しないよう、連続衝突判定または線分スイープを使用。

## 5. 難易度曲線
- **序盤（1本）**：打点で軌道と回転を操る基本を習得。開始直後から左右へ緩やかに動くが、無理なランダム加速はない。
- **中盤（2本）**：どちらの瓶を先に救うかを判断。位置取りと弾の飛行時間を読む。
- **後半（3本）**：3本の軌道を予測し、次に撃ちやすい位置へ運ぶ。反射神経と計画の両方を要求。
- ビン追加は命中回数による。警告表示を約1秒出し、上部の安全な位置から出現。既存瓶が床際にいる場合は出現を延期。
- v0.1では風、障害物、重量差、変形、アイテム、敵は導入しない。

## 6. スコアとフィードバック
- 命中：+1点。
- 重心近くを捉えた安定打：PERFECT +2点（命中位置と結果の両方で判定）。
- 床の近くでの救出：SAVE +2点。位置の基準はテストで調整。
- 追加瓶の条件はスコアではなく総命中回数を使い、ボーナスで難易度が急上昇しないようにする。
- 常時表示：SCORE / BEST / 現在の瓶数。終了画面：スコア、ベスト、最大維持数、RETRY。
- 命中時は短い「ポンッ＋ガラスの響き」、光点、回転が読める短い軌跡。床への衝突は明瞭な「パリン！」と破片演出（即リトライ可能）。
- 色変化、音階による楽曲生成、コンボ演奏はベル案の独立企画として保留。ビンでは音楽要素を盛りすぎない。

## 7. 画面とアート
- 縦9:16。設計基準は360×640論理座標、720×1280表示に対応。PCの縦長ウィンドウでも遊べる。
- 暗めの単色背景、明るい透明グリーンのビン、首と胴と底が一目で分かるシルエット。小さなレトロアーケード風。
- 上：スコア。中央：瓶が動く余白。下：可動式の空気砲と失敗ライン。
- 物理角度と描画角度を一致させる。瓶のラベルを目印に回転が見えるようにする。
- 長いチュートリアルは作らず、スタート前に「MOVE / SHOOT / DON'T DROP」の3語を示す。最初の数発は簡単に当てられる配置。

## 8. 技術方針
- ブラウザ配布を優先して **TypeScript + Vite + Canvas 2D + Planck.js（npmの`planck`）** を第一候補とする。Planck.jsで瓶の質量・形状・回転・衝突を扱い、演出と画面はCanvasに描く。
- 固定タイムステップ60Hz。描画fpsと物理挙動を分離し、30/60/120Hz相当で結果の大きな差が出ないよう検証。
- 物理パラメータ、瓶形状、生成条件、得点規則は設定データとして分離。デバッグ機能では発射位置、接触位置、速度、角速度、当たり判定、命中統計を可視化。
- 音はブラウザのユーザー操作後に開始。ベストスコアはローカル保存。外部通信・アカウント不要。

## 9. 実装順と受入条件
1. **Graybox**：瓶1本、空気砲、横移動、発射、重力、床で終了。形状・回転をデバッグ表示。
2. **打点の気持ちよさ**：中央・左・右への命中結果を調整。命中で必ず視認できる再上昇。狙った方向への変化が説明可能。
3. **一周の完成**：スコア、SE、破損、即RETRY、BEST保存。スタートから結果まで遊べる。
4. **複数化**：2本目と3本目、生成予告、壁反射、瓶同士の衝突。
5. **調整と検証**：スマホの二指操作、ブラウザ、fps差、難易度、画面比率。

**動作受入**：
- 10回繰り返しても同じ初期条件と同じ入力で類似した軌道になる（決定的物理）。
- 中心命中と偏心命中で、回転量・軌道に再現性ある違いが出る。
- 1本・2本・3本で破綻せず、全瓶の失敗ライン判定が正確。壁に挟まったまま固まらない。
- PC／Androidブラウザで移動と射撃が両立。タッチ中にスクロールしない。
- リトライで状態が完全初期化。ベスト保存が継続。
- 30fpsと60fpsで難易度が不当に変わらない。

**体験受入（小人数の観察、未検証）**：初見で「落とさず撃ち上げる」が理解できるか、偏心打ちの結果を学習できるか、落とした直後に再挑戦したくなるかを観察する。平均プレイ時間よりも「何を試して失敗したか」と「もう1回の理由」を優先して記録。

## 10. v0.2以降の拡張候補（今は作らない）
- 空瓶／中身入り／細長瓶などの重さ・重心差。
- ラベル・形状違いと瓶固有の音。
- 追加ルールのないDAILYシード、画像共有、リプレイ。
- 風や障害物は、3本制の熟達が確認できてから検討する。

**判断の優先順位**：物理的に正確かより、打点と結果が分かるか。見た目の豪華さより、10発撃って楽しいか。難易度の高さより、自分が上達できると感じるか。
